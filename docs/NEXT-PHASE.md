# خارطة الطريق: المرحلة القادمة — الفصول والدرجات

> وثيقة عمل داخلية — خلاصة بحث وقرارات يوليو 2026. المرجع التنفيذي عند بدء التنفيذ.

## 1) قرار بيئة التطوير (محسوم بالبحث)

**البقاء على «بلا أدوات بناء» (No-Build)**: HTML + ES Modules أصلية، بلا Vite ولا npm.

مستند إلى إجماع الخبراء 2024-2026 لهذا الصنف من المشاريع (مشرف واحد، بلا تبعيات ثقيلة، أولوية للعمل دون اتصال والاستمرارية):
- Rails 8 جعل «لا بناء» إعداده الافتراضي الرسمي (نوفمبر 2024)
- DHH: «You Can't Get Faster Than No Build» (2023)
- Julia Evans: أنظمة البناء لا تستحق كلفتها للمشاريع الفردية الصغيرة (2023)
- Jeff Huang «Designed to Last»: كل تبعية إضافية هشاشة إضافية

**ننتقل إلى Vite فقط عند تحقق أحد هذه** (لا ينطبق منها شيء حاليًا):
1. فريق تطوير متعدد يحتاج إعدادات موحدة
2. مكتبات خارجية لا تعمل بلا تحويل
3. تجاوز مئات الوحدات الصغيرة مع تراجع أداء **مقيس** (درس Khan Academy)
4. حاجة حقيقية لـ TypeScript متقدم (غير قابل للمحو erasable)

## 2) هدف المرحلة القادمة

ربط المنصة بإدارة فصول ورصد أداء موحد:
- انضمام المتدرب لفصل معين بكود
- رفع درجات المنصة (نقاط التفتيش، XP، المهام) تلقائيًا عند توفر الشبكة
- رصد المدرب لدرجات الاختبارات الورقية في نفس المكان
- إسناد تمارين إضافية تحفيزية بمكافآت XP

**المبدأ الحاكم**: المنصة الحالية تبقى كما هي (تعلم كامل دون اتصال) — نضيف *طبقة مزامنة رقيقة* فوقها، لا إعادة بناء.

## 3) الاختيار التقني (مؤكد بأرقام يوليو 2026)

### الخيار الأول: Supabase
| البند | التفصيل |
|---|---|
| الخطة المجانية | Postgres 500MB، ‏50K مستخدم نشط شهريًا، طلبات غير محدودة، 5GB نقل |
| الدخول بلا إيميل | Anonymous Sign-Ins مدمجة — تناسب نمط كود الفصل |
| لوحة المدرب (مرحلة أولى) | محرر الجداول المدمج Table Editor — كجدول بيانات، بلا تطوير |
| تنبيه | المشروع المجاني يتوقف بعد أسبوع خمول — استخدام المتدربين اليومي يمنعه عمليًا |
| الاستقرار | تمويل 500M$ بتقييم 10.5B$ (يونيو 2026)، أسعار ثابتة منذ 2021 |

### الخيار الثاني (انتقالي أخف): Google Sheets + Apps Script
الجدول نفسه هو لوحة المدرب. يكفي لفصول 20-30 متدربًا. يُرحَّل لاحقًا إلى Supabase.

### مستبعد
- **Firebase**: قوي في المزامنة لكن الكونسول ليس لوحة مدرب وقفل المورد أعلى
- **Appwrite**: يوقف المشروع بعد 7 أيام من خمول *المطوّر* حتى لو كان الطلاب نشطين + سجل رفع أسعار
- **Cloudflare D1**: بلا مصادقة ولا لوحة جاهزة — جهد هندسي بحت
- **PocketBase**: يتطلب إدارة خادم ونسخًا احتياطية

## 4) قرارات التصميم الملزمة

1. **نمط الانضمام** (نمط Kahoot/Google Classroom): كود فصل 6 محارف يوزعه المدرب + كنية يختارها المتدرب + UUID يولَّد محليًا في localStorage يقوم مقام الحساب. المدرب يستطيع تعطيل/تجديد الكود.
2. **الخصوصية (نظام PDPL السعودي)**: لا تُرفع أسماء حقيقية للسحابة إطلاقًا — كنية + معرف عشوائي + درجات فقط. قائمة المطابقة (كنية ↔ اسم حقيقي) تبقى لدى المدرب محليًا. هذا تقليل بيانات وأسماء مستعارة وفق أفضل الممارسات، وليس إعفاءً قانونيًا رسميًا.
3. **المزامنة دون اتصال**: **لا** اعتماد على Background Sync API (غير مدعومة في iPhone/Firefox إطلاقًا). النمط: «صندوق صادر» يدوي (~100 سطر): كتابة محلية بحالة pending + UUID كمفتاح منع تكرار، ثم محاولة رفع عند: حدث online، مؤقت دوري، فتح التطبيق.
4. **جداول قاعدة البيانات**: `classes` (كود، اسم، مدرب) — `students` (uuid، كنية، فصل) — `quiz_results` (طالب، درس/اختبار، درجة، نوع: منصة/ورقي) — `assignments` (فصل، تمرين، مكافأة XP، موعد).

## 5) مراحل التنفيذ

| المرحلة | المحتوى | التقدير |
|---|---|---|
| **2أ** | إعداد Supabase + الجداول + شاشة الانضمام بالكود + صندوق الصادر + رفع درجات المنصة | الأساس — أسبوع عمل متقطع |
| **2ب** | إدخال درجات الاختبارات الورقية (من محرر الجداول) وعرضها للمتدرب في «ملفي» | بسيطة بعد 2أ |
| **2ج** | التمارين الإضافية الموجهة بمكافآت XP (تظهر كمهام خاصة في الخريطة) | متوسطة |
| **2د** | لوحة مدرب مخصصة داخل الموقع (بدل محرر Supabase) | عند الحاجة فقط |

**متطلب من مؤلف المقرر قبل البدء**: إنشاء حساب Supabase مجاني.
